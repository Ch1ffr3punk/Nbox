NaClbox Public Key Server — Administrator GuideA small PHP + SQLite web app that lets users register, log in, and publishtheir NaClbox public key so others can look them up.This guide is written in the order you should execute it. Do not skipStep 0 — the domain must resolve to your server before Let's Encrypt canissue a certificate.Deployment target: HTTPS on port 443 with a Let's Encrypt certificate,served by nginx (Apache variant included in §7).> PHP version note: This guide uses PHP 8.4 in all examples (the> version installed on the reference server). If you run a different version,> replace `php8.4` / `php8.4-fpm.sock` with your version (e.g. `php8.3`).> §2.3 shows how to detect the installed version and socket name.---Prerequisites: hostname and DNS (do this first!)Before touching the server or requesting a certificate, the domain must beset up correctly. Let's Encrypt validates that you control the domain byconnecting to it on port 80 — this only works if DNS already points to yourserver.0.1 Choose the hostnamePick the fully-qualified domain name (FQDN) the app will be served under, e.g.:keys.example.orgUse this exact name consistently everywhere below (nginx `server_name`,certbot `-d`, etc.).0.2 Create the DNS A record (and AAAA if IPv6)At your DNS provider, create:Type	Name	Value	TTLA	`keys`	`<your server IPv4>`	300AAAA	`keys`	`<your server IPv6>`	300The Name is the subdomain part (`keys` for `keys.example.org`). Someproviders want the full FQDN — follow their UI.The Value must be the public IP of your server (not a private10.x / 172.16.x / 192.168.x address).If you don't have IPv6, skip the AAAA record. Do not add a broken AAAArecord — Let's Encrypt may try IPv6 first and fail.0.3 Set the server's hostname (optional but recommended)On the server:sudo hostnamectl set-hostname keys.example.orgAdd it to /etc/hosts so local resolution is consistent:127.0.1.1 keys.example.org keys0.4 Verify DNS propagationFrom your local machine (not the server):dig +short keys.example.org Adig +short keys.example.org AAAAThe A record must return your server's public IPv4. If it returns nothing,wait (TTL, usually a few minutes) and retry. You can also checkhttps://dnschecker.org.Do not continue until DNS resolves correctly. Certificate issuance willfail otherwise.0.5 Ensure ports 80 and 443 are reachablePort 80 must be open from the internet — Let's Encrypt uses it for theACME HTTP-01 challenge (and for renewals).Port 443 is where the app will be served.If your server is behind a router/NAT, forward both ports to it. If you usea cloud firewall (AWS Security Groups, Hetzner Firewall, etc.), allow themthere as well.Quick check from your local machine once the server is up:curl -I http://keys.example.org/You should get some HTTP response (even a 404 or 502 is fine at thisstage — it proves the port is reachable and nginx is listening).RequirementsLinux server (Debian/Ubuntu or similar) with root/sudoPHP 8.4 (or 8.0+) with the following extensions:pdo_sqlite — database accesssqlite3 — SQLite drivermbstring — multibyte string functions (mb_strlen, mb_strtolower)openssl — for random_bytes() / HMAC (usually built-in)A web server: nginx (recommended) or ApacheThe domain from Step 0 pointing to your server's public IPPorts 80 and 443 reachable from the internet1.1 Verify required PHP extensionsAfter installing PHP, confirm all required modules are loaded:php -m | grep -E 'pdo_sqlite|sqlite3|mbstring|openssl'Expected output — all four lines present:mbstringopensslpdo_sqlitesqlite3If any module is missing, install it:sudo apt install php-sqlite3 php-mbstringsudo systemctl restart php8.4-fpmImportant: PHP modules are only loaded when PHP-FPM (re)starts.After installing a module, you must restart PHP-FPM — otherwise themodule won't be available to the web app:sudo systemctl restart php8.4-fpm2.0 Install the web stack2.1 Install packagessudo apt updatesudo apt install nginx certbot python3-certbot-nginx \                 php-fpm php-sqlite3 php-mbstring2.2 Start and enable PHP-FPMsudo systemctl enable --now php8.4-fpmsystemctl status php8.4-fpm --no-pagerExpected: active (running).2.3 Detect the PHP-FPM socket nameThe socket name depends on the installed PHP version:ls /run/php/Example output:php-fpm.sock  php8.4-fpm.pid  php8.4-fpm.sockUse the phpX.Y-fpm.sock matching your version in the nginx config(fastcgi_pass unix:/run/php/php8.4-fpm.sock;).If the directory /run/php/ does not exist, PHP-FPM is not installed or notrunning — go back to §2.1 / §2.2.3.0 Deploy the applicationPlace the application in /var/www/naclbox/:/var/www/naclbox/├── keyserver.php      # the application (single file)├── keysever.db        # SQLite DB (created automatically on first run)└── .csrf_secret       # HMAC secret (created automatically)sudo mkdir -p /var/www/naclboxsudo chown -R www-data:www-data /var/www/naclboxsudo chmod 750 /var/www/naclboxCopy keyserver.php into that directory (e.g. with scp or by pasting itinto an editor). After the first request creates the files, tightenpermissions:sudo chmod 640 /var/www/naclbox/keysever.dbsudo chmod 600 /var/www/naclbox/.csrf_secretImportant: keysever.db and .csrf_secret must not be web-accessible.The nginx config below blocks them explicitly.Filename note: This guide uses keyserver.php as the applicationfilename. If you named it differently (e.g. keysever.php), adjust theindex and try_files directives in §4/§6 accordingly.Step 4a — nginx: initial HTTP-only configWe start with an HTTP-only config so that Certbot can validate the domainon port 80. The HTTPS server block is added in §6 after the certificateexists. This avoids the classic "certificate file not found" error.Create /etc/nginx/sites-available/naclbox:nginxserver {listen 80;listen [::]:80;server_name keys.example.org;    # Let's Encrypt ACME challenge    location /.well-known/acme-challenge/ {        root /var/www/html;    }    # Everything else: serve the app over HTTP for now.    # After the cert is issued, this block will be changed to redirect to HTTPS.    root /var/www/naclbox;    index keyserver.php;    location ~ /\.(csrf_secret|ht) { deny all; return 404; }    location ~* \.(db|db-wal|db-shm)$ { deny all; return 404; }    location / {        try_files $uri $uri/ /keyserver.php?$query_string;    }    location ~ \.php$ {        include snippets/fastcgi-php.conf;        fastcgi_pass unix:/run/php/php8.4-fpm.sock;        fastcgi_param HTTPS off;    }    client_max_body_size 1m;    server_tokens off;}Enable and reload:sudo ln -s /etc/nginx/sites-available/naclbox /etc/nginx/sites-enabled/sudo rm -f /etc/nginx/sites-enabled/defaultsudo nginx -tsudo systemctl reload nginxAt this point the app should be reachable at http://keys.example.org/.Step 4b — obtain the Let's Encrypt certificateNow that HTTP works and DNS is verified, request the certificate:sudo certbot --nginx -d keys.example.orgCertbot will:validate the domain via the HTTP-01 challenge on port 80,write the certificate to /etc/letsencrypt/live/keys.example.org/,modify your nginx config (or prompt you to) to add the SSL server block,set up automatic renewal via a systemd timer.If Certbot reports "cannot load certificate ... No such file or directory",it means the config already referenced a cert that doesn't exist yet. Use thestandalone method instead:sudo systemctl stop nginxsudo certbot certonly --standalone -d keys.example.orgsudo systemctl start nginxThen continue with §6 below to add the HTTPS server block manually.Step 4c — final nginx config (HTTPS on port 443)Replace /etc/nginx/sites-available/naclbox with the full config below.This is the production-ready version: HTTP redirects to HTTPS, ACMEchallenge stays reachable, PHP 8.4 socket, robust try_files routing,sensitive files blocked.nginx---------------------------------------------------------------------------HTTP – only for ACME challenge and redirect to HTTPS---------------------------------------------------------------------------server {listen 80;listen [::]:80;server_name keys.example.org;    # Let's Encrypt ACME challenge (must stay reachable for renewals)    location /.well-known/acme-challenge/ {        root /var/www/html;    }    # Everything else: redirect to HTTPS    location / {        return 301 https://$host$request_uri;    }}---------------------------------------------------------------------------HTTPS – the actual application---------------------------------------------------------------------------server {listen 443 ssl;listen [::]:443 ssl;http2 on;server_name keys.example.org;    # --- TLS ---    ssl_certificate     /etc/letsencrypt/live/keys.example.org/fullchain.pem;    ssl_certificate_key /etc/letsencrypt/live/keys.example.org/privkey.pem;    ssl_protocols       TLSv1.2 TLSv1.3;    ssl_ciphers         HIGH:!aNULL:!MD5;    ssl_prefer_server_ciphers on;    ssl_session_cache   shared:SSL:10m;    ssl_session_timeout 10m;    # --- Security headers ---    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;    add_header X-Content-Type-Options "nosniff" always;    add_header X-Frame-Options "DENY" always;    add_header Referrer-Policy "no-referrer" always;    # --- Application root ---    root /var/www/naclbox;    index keyserver.php;    # --- Block direct access to sensitive files ---    location ~ /\.(csrf_secret|ht) {        deny all;        return 404;    }    location ~* \.(db|db-wal|db-shm)$ {        deny all;        return 404;    }    # --- Main routing ---    location / {        try_files $uri $uri/ /keyserver.php?$query_string;    }    # --- PHP handling ---    location ~ \.php$ {        include snippets/fastcgi-php.conf;        fastcgi_pass unix:/run/php/php8.4-fpm.sock;        fastcgi_param HTTPS on;    }    # --- Misc hardening ---    client_max_body_size 1m;    server_tokens off;}Test and reload:sudo nginx -tsudo systemctl reload nginxOpen https://keys.example.org/ — the app should load over HTTPS.RenewalCertbot installs a systemd timer that renews certificates automatically.Verify it works:sudo certbot renew --dry-runIf you used the standalone method (nginx stopped during issuance), set uprenewal hooks so renewals also work without manually stopping nginx:/etc/letsencrypt/renewal-hooks/pre/stop-nginx.sh:#!/bin/bashsystemctl stop nginx/etc/letsencrypt/renewal-hooks/post/start-nginx.sh:#!/bin/bashsystemctl start nginxsudo chmod +x /etc/letsencrypt/renewal-hooks/pre/stop-nginx.shsudo chmod +x /etc/letsencrypt/renewal-hooks/post/start-nginx.shsudo certbot renew --dry-runApache variant (alternative to nginx)If you prefer systemctl reload apache2sudo certbot --apache -d keys.example.orgFirewallAllow only what's needed:sudo ufw allow 80/tcpsudo ufw allow 443/tcpsudo ufw enable(Adjust if you use nftables/firewalld or a cloud firewall.)Port 80 must stay open permanently: Let's Encrypt renewals still use theHTTP-01 challenge every ~60 days.Application configuration (constants in keyserver.php)At the top of keyserver.php:Constant	Default	MeaningDB_FILE	DIR/keysever.db	SQLite database pathUSERNAME_MAX_LENGTH	50	Max username lengthPASSWORD_MIN_LENGTH	8	Min password lengthCSRF_SECRET_FILE	DIR/.csrf_secret	HMAC secret fileRL_LOGIN_MAX_ATTEMPTS	5	Failed logins allowedRL_LOGIN_WINDOW	900	Login window (seconds)RL_REGISTER_MAX_ATTEMPTS	3	Registrations allowedRL_REGISTER_WINDOW	3600	Registration window (seconds)RL_CLEANUP_PROBABILITY	5	1-in-N requests triggers cleanupRate limiting: how it worksTwo buckets: login and register, stored in the rate_limits table.Login: counts failed attempts per IP + username (hashed). Asuccessful login clears the counter for that pair.Register: coukeyservernts attempts per IP.Identifiers are SHA-256 hashed; raw IPs/usernames are not stored.Rows older than 24 h are deleted periodically (probabilistic cleanup,~1 in every 5 POST requests).Behind a reverse proxy (Cloudflare, load balancer, ...)client_ip() uses $_SERVER['REMOTE_ADDR'] by default — this is thesafe choice and cannot be spoofed by clients. If the app runs behind atrusted proxy, REMOTE_ADDR will be the proxy's IP for everyone, andrate limiting would effectively be global. In that case, editclient_ip() to read the real client IP from a header only after verifyingthe request came from your trusted proxy range. Do not blindly trustX-Forwarded-For — clients can forge it.BackupsThe only state is keyserver.db (and .csrf_secret, which you should also backup so CSRF tokens stay valid across restores). Use SQLite's online backupfor consistency:sqlite3 /var/www/naclbox/keysever.db ".backup '/backup/keysever-$(date +%F).db'"Store backups off-site. Test restores regularly.Logs and monitoringPHP errors → error_log(); check PHP-FPM / nginx error logs:/var/log/nginx/error.log/var/log/php8.4-fpm.log (or similar)Rate-limit events are not logged by default. To monitor abuse:sqlite3 /var/www/naclbox/keysever.db   "SELECT bucket, COUNT(*) FROM rate_limits GROUP BY bucket;"Security checklistDNS A/AAAA record set and verified (Step 0)Ports 80 and 443 reachable from the internetHTTPS enforced (port 80 → 301 → 443)keyserver.db, keyserver.db-wal, keyserver.db-shm, .csrf_secret not web-accessiblesession.cookie_secure active (automatic once $_SERVER['HTTPS'] === 'on')Rate limiting active for login and registrationPasswords hashed with password_hash() / verified with password_verify()CSRF tokens on all POST forms (HMAC + timestamp + nonce)Backups of keysever.db + .csrf_secretCertificate auto-renewal verified (certbot renew --dry-run)OS and PHP packages kept up to dateTroubleshootingSymptom	Likely cause / fixcannot load certificate ... No such file during certbot --nginx	Config referenced a cert before it existed. Use certbot certonly --standalone first (§5), then install the HTTPS block manually (§6).Certbot challenge fails	DNS not pointing to the server, or port 80 blocked. Re-check Step 0 and firewall.the "listen ... http2" directive is deprecated (warning only)	Use listen 443 ssl; + http2 on; (already in §6)."client_max_body_size" directive is duplicate	The directive appears twice in the same server block. Remove one occurrence.404 Not Found from nginx	Filename mismatch between index/try_files and the actual file on disk, or missing $uri/ in try_files. Check ls /var/www/naclbox/ and sudo nginx -T | grep try_files.502 Bad Gateway	PHP-FPM socket path in nginx config doesn't match installed PHP version. Check ls /run/php/ and grep fastcgi_pass /etc/nginx/sites-available/naclbox.500 Internal Server Error	PHP error. Check /var/log/php8.4-fpm.log and nginx error log. Often a missing PHP module (php -m | grep ...) or wrong file permissions."Database error"	keysever.db not writable by www-data; fix ownership/permissions.CSRF "Invalid form submission"	.csrf_secret changed (e.g. restored DB without secret) or token older than 1 h; reload page.Login always fails	Check PHP-FPM error log; verify password_verify works (bcrypt available).Rate limit hit immediately	You're behind a proxy — see §10; or clear rate_limits table.php -m shows missing module after install	PHP-FPM was not restarted. Run sudo systemctl restart php8.4-fpm.Uninstall / resetsudo rm /etc/nginx/sites-enabled/naclboxsudo systemctl reload nginxsudo certbot revoke --cert-name keys.example.org   # optionalsudo rm -rf /var/www/naclboxLicense / attributionInternal admin documentation.
